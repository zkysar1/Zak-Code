# RISKS

Risk register for Zak Code. Likelihood and Impact are L / M / H. Status is Open, Mitigating, or Accepted. This expands the seed register in `docs/RISKS.md`.

| Risk | Category | Likelihood | Impact | Mitigation | Status |
| --- | --- | --- | --- | --- | --- |
| Accidentally copying leaked/proprietary (Claude Code) source into the repo | Legal/IP | M | H | Clean-room rule (Guardrails §1); reference kept outside repo at `_zakcode_research\` and gitignored; re-express in our own design + ADRs; pre-commit check that ignored research paths aren't staged; diff review | Mitigating |
| Reference material or `.env` committed by accident | Legal/IP | M | H | `.gitignore` covers `_research/`, `_zakcode_research/`, `claw-code-main/`, `.env*`; never weaken ignores; verify staged paths before commit | Mitigating |
| Remote code execution / data loss via file & shell tools | Security (RCE) | M | H | Permission gate enforced in core; destructive-op confirmation showing exact command/diff; arg-vector exec, timeouts, output caps, scrubbed env, denylist; fail-closed | Mitigating |
| Path-escape / writes outside workspace (`..`, symlinks, absolute paths) | Security | M | H | Resolve to real absolute path; reject escapes; deny writes outside root; protect `.git`, `.env`, venv, research dir | Mitigating |
| API key leakage via logs, commits, errors, or model context | Security (key leakage) | M | H | `.env` gitignored; report presence only, never value (the `info` panel names a key's *source*, never its value); redact logs/tracebacks/session files; keep secrets out of prompts and child-process env. Keys in `~/.zakcode/.env` (D20) follow the **user** rather than one project — a wider blast radius if that file is exposed — but enter `os.environ` exactly like workspace keys, so the subprocess scrub and redaction above cover them unchanged | Mitigating |
| Prompt injection via tool output / file / web content driving privileged actions | Security (prompt injection) | M | H | Treat all tool/web output as untrusted data; never auto-execute embedded instructions; trust-boundary delimiting; gate + confirm; human-in-loop for ingest+egress/destructive chains. ✅ **Per-task tool-exposure filter** (`ZAKCODE_TOOL_EXPOSURE_ALLOW`/`_DENY`; `ToolRegistry.set_exposure_filter`, self-remediation Step 4): an operator can narrow the model-facing toolset to a task-appropriate subset (e.g. deny `bash,powershell,mcp__*` for a read-only research task) — the single most effective injection defense per AgentDojo, since a tool that's never advertised AND is rejected at the execution seam can't be hijacked. Exposure-only; composes with the deny-first gate + floors. Residual: still best-effort (the operator must scope the task; an over-broad scope re-widens the surface) and not a substitute for the Step 3 sandbox. | Mitigating |
| Unintended network egress / exfiltration via tools | Security | M | H | No phone-home; `web_search` egress goes only to the configured search backend (ddgs/Tavily/SearXNG); `web_fetch` can reach arbitrary **public** URLs (an egress surface comparable to `bash curl`) but is SSRF-guarded against the internal network; fetched/search content is treated as untrusted + defanged; endpoints from config not model output. **Two opt-in egress controls:** `ZAKCODE_WEB_ALLOWED_DOMAINS` restricts `web_fetch` to named domains (+ subdomains, enforced per redirect hop); `ZAKCODE_WEB_FETCH_CONFIRM` escalates every `web_fetch` to a (session-grantable) confirmation prompt — blocked outright in `deny` mode. Residual: with neither set (the default), `web_fetch` is READ_ONLY/ungated and can reach any public URL, so a query-string exfil is possible there — an accepted default posture (comparable to `bash`), now closeable by either control. **Subprocess egress** (`bash`/`powershell` reaching the network, e.g. `curl`): the opt-in `ZAKCODE_EGRESS_PROXY` routes child processes through a localhost **domain-allowlisting proxy** (`ZAKCODE_EGRESS_ALLOWED_DOMAINS`; empty = deny all) so cooperating clients (curl/pip/git/wget/HTTP libs) are confined to the allowlisted domains on the standard web ports (80/443) — other hosts, ports (e.g. CONNECT to SSH/SMTP/DB), and non-HTTP schemes are refused. Residual: best-effort (a process ignoring `*_PROXY` env, e.g. raw sockets / `--noproxy`, bypasses it; an allowlisted domain that resolves to a private IP is still reached — the allowlist is the policy); kernel-enforced network isolation is backlog | Mitigating |
| SSRF via `web_fetch` (model-supplied URL reaching internal services / cloud metadata, incl. DNS rebinding) | Security (SSRF) | M | H | `_http`: only `http(s)`; refuse loopback / private (RFC1918) / link-local (incl. `169.254.169.254` metadata) / reserved / multicast for IP literals, **obfuscated IPv4 (decimal/hex/octal) and IPv4-mapped IPv6**, AND resolved hostnames (**every** resolved IP checked); **resolve once and connect to the validated IP** (Host + TLS SNI preserved) so a DNS rebind can't swap check-time vs connect-time target; redirects followed manually and re-validated + re-pinned per hop; downloads bounded (no decompression bomb; Content-Length pre-check; byte cap); fail-closed on unparseable/unresolvable hosts | Mitigating |
| Provider/API drift (litellm, OpenAI, Ollama schema or behavior changes) | Provider/Vendor | M | M | Thin provider layer isolates vendor specifics; pin versions in `uv.lock`; integration tests against first-class targets; config-only provider swap | Open |
| Vendor pricing/policy/availability change for a relied-upon model | Provider/Vendor | M | M | Vendor-agnostic by construction; fallback model config; local Ollama path keeps tool usable offline/zero-cost | Mitigating |
| Local models lacking native tool-calling produce malformed/no tool calls | Reliability | H | M | Provider-layer prompted-tool-protocol fallback; strict tool-input validation (pydantic); recommend tool-capable local models (e.g. qwen2.5-coder); retries with repair | Open |
| Scope creep / never-ending parity chase with Claude Code | Scope creep | H | M | Milestones with exit criteria (`ROADMAP.md`); tiered parity matrix (`PARITY.md`) targeting capability not byte-parity; explicit non-goals in charter | Mitigating |
| Context window / cost blowups during long sessions | Context/Cost | M | M | ✅ M8 shipped real-token-count auto-compaction (`agent/compact.py` `Compactor`, fired pre-turn from the loop at ~80% of the provider's context window; LLM summary, recent turns kept verbatim, tool-pair-safe, idempotent; `/compact`). Plus per-session iteration cap (`ZAKCODE_MAX_ITERATIONS`); bounded tool output. Residual: per-tool-type result truncation + large-output offload still deferred. | Mitigating |
| Supply-chain compromise via a new/transitive dependency (incl. an agent autonomously installing a typosquatted/malicious package while self-remediating) | Security/Supply-chain | L | H | Vet + license-check new deps; pin & commit `uv.lock`; no post-install/fetch-execute steps. ✅ **Declared-dependency gate** (`ZAKCODE_DEPENDENCY_GATE`, default on; `deps_gate.py` + `PermissionPolicy`): an install of a package the project's manifests/lockfile don't declare escalates to a confirmation prompt and **hard-denies in `autonomous`** (where there's no prompt and no execution sandbox yet) — so the self-fix path can only auto-install what the repo already vouches for. Launcher-aware + ecosystem-tagged (catches `python [-flags] -m pip` / `uv pip|tool install` / `uvx` / versioned `pip3.11` / full-interpreter-path / `env`+`FOO=bar` prefix / `&`+subshell forms), tighten-only, un-waivable by a session grant or a hook rewrite; `uv sync`/`npm ci`/declared/editable installs pass. Self-remediation Step 1 (`docs/SELF-REMEDIATION.md`). Residual: (1) the install-detection parser is **best-effort** — a deliberately obfuscated install (nested `bash -c "…"`, `xargs`/`eval`, base64/`$()`-decoded) can still slip it; reliably parsing arbitrary shell is unsound, so this is by design contained by the Step 3 sandbox, not the parser. (2) No execution sandbox yet (Step 3) — a *declared* dependency that is itself compromised still runs; the gate scopes *which* packages, not what they do once installed. | Mitigating |
| Autonomous self-modification of sensitive files (rewrite `.claude/` config to escalate own permissions, overwrite `.env` secrets, tamper installed deps in the venv, corrupt `.git/`) — esp. under a blanket "allow" grant or loose mode | Security/Self-modification | L | H | ✅ **Protected-path floor** (`PROTECTED_PATH_PATTERNS` + `PermissionPolicy._protected_path_reason`, self-remediation Step 2): a write/edit whose path matches `.git/` / `.env` (not `.env.example`) / the venv / `.claude/` never auto-allows — it escalates to a (session-grantable) prompt under `allow`/`acceptEdits` and **hard-denies in `autonomous`**, even under a session grant or per-tool trust override (the grant fast-paths re-decide; re-applied to a hook-rewritten call). Operator extras via `ZAKCODE_PROTECTED_PATHS`. Residual: the floor scans the write-tool path arg, not arbitrary shell (a path in a command is usually a read/execute, so scanning over-blocks) — a shell-driven write to a protected path is best-effort residual contained by the Step 3 sandbox. | Mitigating |
| Permission model bypassed by a client (CLI/server) instead of core | Security/Architecture | L | H | Gate enforced in core engine, not clients; clients only render prompts; tests assert privileged tools fail closed without a grant | Open |
| Maintainability erosion (untyped boundaries, drift between docs and code, core/interface leakage) | Maintainability | M | M | Typed pydantic boundaries; ruff + mypy + pytest before done; "docs travel with code"; core/interface separation; small reviewable changes | Open |
| New behavior ships without tests, reducing reliability over time | Maintainability/Reliability | M | M | New behavior ships with tests; CI-style verification loop; review gate | Open |
| Client-supplied per-request `model` routes prompts/cost to an unintended provider the host has creds for | Security/Cost | L | M | ✅ Server now supports **bearer auth** (`ZAKCODE_AUTH_TOKEN` → `Authorization: Bearer` required on every route except `/health`, constant-time compare); `serve` **refuses a non-loopback bind** without a token unless `--insecure`; and an optional **model allowlist** (`ZAKCODE_ALLOWED_MODELS`) rejects (400) any override not on the list. The override still preserves the operator's permission/workspace posture (model-only swap). | Mitigating |
| WebSocket catch-all forwards raw exception text (`type: error`) to the connected client, possibly echoing filesystem paths / internals | Security/Info-leak | L | L | ✅ Fixed: the WS turn catch-all now logs the real detail server-side (`logger.exception`) and sends the client a **generic** `{"type":"error","detail":"internal error"}` frame; the socket still stays alive. | Mitigating |
| Concurrent turns on one session corrupt the transcript (shared message list + last-writer-wins store) | Reliability/Data-integrity | M | M | REST/SSE refuse a second in-flight turn per session with 409; WS enforces one turn at a time per connection. Residual: cross-channel (WS+REST) concurrency on the same session is still possible — to be unified when M4 sub-agents share sessions. | Mitigating |
| Provider keys reach agent-spawned subprocesses: `load_settings()` exports `.env` into `os.environ` (D10), and `bash`/`powershell` children inherit the parent environment — an agent-run script can read the host's `OPENAI_API_KEY`/`GROQ_API_KEY`/etc. (Pre-existing for OS-level env keys; the `.env` loading widens who is exposed.) | Security (key leakage) | M | M | ✅ Scrubbed by default since PR-3: the loop hands subprocess tools a scrub list (`zakcode.secrets.provider_key_env_names` — known names + the `*_API_KEY` suffix rule), removed from the child env LAST so the egress overlay can't resurrect a key. Opt out via `ZAKCODE_SUBPROCESS_INHERIT_PROVIDER_KEYS=true` for workflows whose scripts legitimately call a provider. zakcode itself still never logs/echoes key values. Residual: the opt-out is global (not per-key), and non-`*_API_KEY`-named credentials (e.g. `AWS_SECRET_ACCESS_KEY`) are not in the default list. | Mitigating |
